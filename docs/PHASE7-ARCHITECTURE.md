# Phase 7 architecture — 7A–7D only

Read both supplied PDFs: phase plan pp17–18; designs A03–A06, A25/A29, S19 and M08. User explicitly authorized Phase 7 while deferring the outstanding Stripe integration purchase. That acceptance gap remains; no admin mark-paid bypass will be added. The courier sandbox permitted by the plan is the default; no real courier credentials or charges.

## Orders and manual entry
Search/filter protected orders, immutable address/price detail, append-only internal notes, timeline and support records. fulfilment.view grants read, fulfilment.manage grants writes, all staff POSTs retain session/MFA/origin/CSRF enforcement. Manual draft uses current active catalogue, shared Pricing, address validation and Checkout stock transaction. Secure one-use payment invitations bind to the customer bag only after token redemption. Manual orders are unpaid; no fictional payment confirmation. While Stripe is disabled, these remain payment-link orders and cannot be dispatched. Unattempted manual invitations expire and release reservations after one hour; ambiguous attempted Stripe requests retain Phase 6 safeguards.

## Fulfilment and courier adapter
Paid/confirmed orders only. Quote a subset of remaining item quantities and a parcel at an active location that actually committed those units. Account for all noncancelled allocations, including uncertain bookings, under an order lock. Phase 6 already deducted on-hand at payment: dispatch never deducts it again. One parcel per fulfilment; split shipments use separate allocations. Persist quote, parcel, fulfilment items, booking attempt, provider receipt, label and tracking events. A quote freezes cost, destination, origin, items and parcel and expires after ten minutes. Review/explicit confirmation precedes label purchase.

Local SandboxCourier has a persistent unique provider receipt keyed by fulfilment ID. It never calls a carrier or purchases postage. Deterministic private SVG labels say SANDBOX / NOT VALID FOR POSTAGE and contain no usable carrier barcode. Configurable timeout-before/timeout-after-once and reject scenarios prove retries use the same request identity. Unknown receipt outcomes retain item allocation. Cancel a draft locally or a booked sandbox label only after adapter void confirmation; cannot cancel dispatched/in-transit/delivered shipments. Cancelling a label releases fulfilment allocation, never reverses payment or restocks the order. No refunds or order cancellation added.

## Tracking, notifications and privacy
Tracking requires reference+email and an expiring one-use email link; neutral request responses avoid order existence disclosure. Link token in URL fragment, removed before POST redemption; hash-only challenge records, encrypted queued delivery payload. Redemption exchanges for a separate 24-hour HttpOnly tracking cookie/capability scoped to one order. Existing bag ownership is not substituted for this verification. Public tracking response contains shipment progress, never street addresses, internal notes, provider labels or staff data. Minimal support request requires verified tracking access and UUID retry key.

Sandbox courier webhook verifies raw-body HMAC/timestamp with a locally configured secret, stable event IDs, known receipt/tracking identity and allowlisted states. Monotonic rank plus occurred-at guard rejects regressions; exception events cannot undo delivered. Cancelled bookings ignore late scans. Events affect shipment/aggregate fulfilment only, never payment/order financial state. A trusted transit scan records physical dispatch if not already dispatched.

Durable notification rows are inserted with state changes; database worker saves deterministic private .eml copies. Tracking/payment-link copies include one-use links; staff API reveals notification status, not tokens. Explicitly local delivery only until real mail is configured. Scheduled dispatch and eligible manual expiry are separate from Stripe reconciliation. Real courier webhooks, real labels, external delivery and Stripe capture remain unverified and must be described honestly.

## Verification and data preservation
Private source/database backups before edits; additive migration, preserve current records/.env. Isolated feature tests for permission/CSRF, unpaid/over-quantity denial, partial fulfilment/origin allocations, retries/timeouts/cancellation, tracking access/isolation/replay/expiry, event signature/dedupe/order, notifications, manual shared pricing/stock and no fake payment. Independent processes race remaining units and label booking. Production frontend builds and browser lifecycle demonstrate two shipments, private label download, customer progress and support with missing/wrong credentials denied. No Phase 8 accounts/returns/refunds.
