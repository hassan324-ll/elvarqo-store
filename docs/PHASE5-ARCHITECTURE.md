# Phase 5 architecture — 26 October 2026

Reviewed plan Phase 05 pp.13–14 and design S01–S12/S38/M01–M03. Preserve Phase 1–4 and staff access. Only storefront shopping discovery/selection is authorized; bag mutations/payments/stock reservations remain Phase 6 and account wishlist sync Phase 8.

Extend Laravel's published-only reads with validated q/collection/colour/size/price/availability filters, stable featured/newest/price ordering and pagination. All variant filters must match one eligible active variant, not different variants on the same product. Return contextual facets and filtered listing prices from the server. Hide empty collections, support a bounded stable-ID batch read for guest saved items, and retain public canonical slug redirects. No database schema migration or data seeds are needed.

Next 16.4 request-time SSR (cacheComponents/partialPrefetching disabled explicitly) will render real home products, collection landing, shop/search listings and product content. No-store fetches, bounded timeouts and request-scoped React memoization avoid stale public prices or draft content. Disable streaming metadata so unavailable/alias product routes can return intentional HTTP 404/308 responses before the body. Canonical origin defaults to https://elvarqo.uk, configurable; all development pages stay noindex unless explicit production indexing opt-in. Filter/search variants are noindex; unfiltered canonical shop/collection/product metadata is defined. No fabricated ratings, certifications, delivery promises or business data.

Public API URL is NEXT_PUBLIC_API_URL; optional CATALOGUE_API_URL supports server access. Image URLs are normalized to the public API origin, not an internal server hostname. Use Laravel's private original/authorized responsive derivative API, image placeholders and recovery controls. Keep concept campaign artwork explicitly labelled until merchant assets arrive; saleable product cards never use concept fixture prices/images.

Client interaction: accessible native radio groups for colour/size, variant-linked galleries, sold-out/missing combinations, confirmed choice and size-guide cm/inches tables with supplier data/variant overrides. Quick selection reuses the same product-selection component. Refresh availability on focus/visibility and every 30 seconds while detail/quick view is open, retain choices and show a failure state without treating stale data as current. Bag handoff v1 is documented as product_id/variant_id/quantity/currency with no trusted browser price or reserved-stock assertion; no bag write is performed.

Guest wishlist uses localStorage elvarqo.wishlist.v1 with at most 50 validated product IDs and optional selected variant IDs, no cached prices/descriptions or staff credentials. Cross-tab synchronization, corrupt/blocked-storage handling and unavailable-item removal are explicit. Fetch current published resources by stable IDs so slug changes work and unpublished items reveal no stale content.

Use isolated SQLite/storage/test products for backend/browser verification. Preserve existing development data and secrets. Verify real catalogue SSR, filter URL reload/back navigation/counts/sorts, empty/error/retry states, keyboard/mobile variant and measurement controls, persistent wishlist, unpublished and old-slug HTTP responses, and Phase 1–4 regression checks. No production account/email/deployment and no Phase 6 work.
